# Развёртывание: Supabase + Vercel

Инструкция составлена по документации сервисов. Реальный деплой в рамках разработки не выполнялся: после первого запуска пройдите [сценарий проверки](DEMO.md) на своём окружении.

## 1. Supabase

1. Создайте проект (регион поближе к пользователям). Пароль базы приложению не нужен.
2. **SQL Editor → New query:** по очереди вставьте и выполните файлы из `supabase/migrations/` в порядке имён:
   1. `20261106000001_schema.sql`
   2. `20261106000002_rls.sql`
   3. `20261107000001_no_show_status.sql`
   4. `20261107000002_booking_rules.sql`
   5. `20261108000001_public_booking.sql`

   Каждый файл выполняйте отдельно и дожидайтесь `Success`. Файл с `no_show` — обязательно отдельным запуском: новое значение enum нельзя использовать в той же транзакции.
3. Демо-данные: выполните `supabase/seed.sql`. Только для демо-проекта (см. «Безопасный доступ к демо» ниже).
4. **Authentication → Providers → Email:** включено. Для демо отключите «Confirm email», иначе регистрация потребует настроенную почту. Для боевого проекта настройте SMTP и оставьте подтверждение включённым.
5. **Authentication → URL Configuration:** после деплоя укажите Site URL (`https://<ваш-домен>`) и добавьте Redirect URL `https://<ваш-домен>/auth/callback`.
6. **Project Settings → API:** скопируйте `Project URL` и ключ `anon public`.

> Никогда не добавляйте ключ `service_role` в Vercel, в Git или в код. Приложение работает только с `anon`-ключом, а доступ к данным ограничивают политики RLS.

## 2. Vercel

1. Загрузите репозиторий на GitHub (убедитесь, что в нём нет `.env.local`: он в `.gitignore`).
2. [vercel.com/new](https://vercel.com/new) → импортируйте репозиторий. Framework Preset определится как Next.js, команды по умолчанию (`npm run build`).
3. **Environment Variables** (Production и Preview):
   - `NEXT_PUBLIC_SUPABASE_URL` — Project URL из Supabase;
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — anon-ключ;
   - `NEXT_PUBLIC_SITE_URL` — `https://<ваш-домен>`;
   - `BOOKING_RATE_SALT` — любая случайная строка (например, вывод `openssl rand -hex 16`).
4. **Node.js version:** 22.x (Project Settings → General).
5. Deploy. После деплоя вернитесь в Supabase и пропишите Site URL / Redirect URL (шаг 1.5).

На Vercel заголовок `x-forwarded-for` выставляет платформа; он используется для лимитов публичной записи.

## 3. Проверка после деплоя

Пройдите [docs/DEMO.md](DEMO.md). Минимум: вход → создание записи в админке → открытие `/book/<slug>` с телефона → запись появилась в панели.

## Безопасный доступ к демо

Seed создаёт аккаунты с **общеизвестным паролем** `Password123!`. Для открытого демо-стенда это допустимо, если соблюдены условия:

- демо развёрнуто на **отдельном** Supabase-проекте, где нет реальных данных;
- публично указывайте вход **администратора** (`pavel@bookly.test`), а не владельца: администратор не может удалить организацию и выдавать роль владельца;
- в README явно сказано, что данные общие и вымышленные, а реальные данные вводить не нужно;
- состояние демо периодически возвращают повторным запуском `seed.sql` (скрипт перезапускаемый и пересоздаёт демо-данные); после этого пароль снова `Password123!`;
- публичная страница записи (`/book/lavanda-demo`) открыта без входа по задумке: она отдаёт только публичные данные и ограничена лимитами.

Если нужен закрытый доступ, смените пароль демо-пользователей (SQL Editor, подставьте свой) и выдавайте его только тем, кому нужно:

```sql
update auth.users
   set encrypted_password = extensions.crypt('ВАШ-НОВЫЙ-ПАРОЛЬ', extensions.gen_salt('bf'))
 where email like '%@bookly.test' or email like '%@borodach.test';
```

Для продакшена с реальными клиентами не используйте seed и демо-аккаунты вообще: регистрируйтесь через `/register`.

## Обновление базы

Новые изменения схемы добавляйте новыми файлами в `supabase/migrations/` и применяйте по порядку; уже применённые файлы не редактируйте.
