# Отчёт о тестировании Bookly

Дата: 2026-11-08. Проверялась production-сборка (`next build` + `next start`) на локальном стенде Supabase
(`supabase/tests/emulator.mjs`: реальные миграции, реальный seed, реальные политики RLS; PostgREST/GoTrue — самодельный
эмулятор). Запросы браузера не подменяются: UI → Next.js → server actions → база.

## Как запустить
```bash
npm run e2e          # Playwright: поднимает эмулятор и production-сервер сам (сборка ~1–2 мин)
npm run e2e:report   # HTML-отчёт
npm run test:db      # RLS, правила записи, публичная запись, загрузчик данных, логика (без браузера)
npx tsc --noEmit && npx eslint . && npm run build
```

## Что проверено
- **Авторизация** (`auth.spec.ts`): регистрация (создаются аккаунт, организация, роль владельца; новая пустая организация открывается на всех страницах); вход; выход; неверный пароль и неизвестный email дают одно и то же сообщение, поля не очищаются; пустая форма останавливается браузером; дубликат email; все 7 защищённых страниц и CSV без входа редиректят на `/login`; роль staff не видит «Настройки», экспорт даёт 403.
- **Клиенты** (`clients.spec.ts`): создание с валидацией (значения сохраняются при ошибке), редактирование, поиск по имени/телефону/email, фильтры, пустой результат, поиск из верхней панели, страница клиента с историей, удаление (отмена и подтверждение, со страницы клиента), CSV (BOM, защита от формул). Каждое изменение сверяется с базой через REST.
- **Услуги и сотрудники** (`catalog.spec.ts`): создание, правка, отключение/включение; специалист с услугами и недельным расписанием с перерывом; ошибки расписания (перерыв вне рабочего времени, один конец перерыва, конец раньше начала); смена услуг и графика; отключение специалиста.
- **Записи** (`appointments.spec.ts`): создание (цена и время окончания фиксируются), предупреждение и отказ БД при пересечении, запись «встык», перерыв и нерабочее время, отключённый специалист не выбирается, редактирование/перенос, статусы (завершена, не пришёл, ожидает), отмена освобождает время, фильтры и поиск; календарь: недели/дни, фильтр по специалисту, создание по клику, перенос перетаскиванием, отказ при перерыве и при занятом времени.
- **Публичная запись** (`booking.spec.ts`, desktop + mobile): полный сценарий до появления записи в списке админки, в календаре и в уведомлениях; невалидные данные (в браузере и в обход него); занятое время (с выбором другого); двойной клик и повторная отправка (ровно одна запись); отправка быстрее человека (ловушка для ботов); прошлое и 60+ дней; выходной день; «любой специалист»; несуществующие адреса.
- **Адаптивность** (`responsive.spec.ts`): нет горизонтальной прокрутки страницы на 320/375/768/1280 px на всех 7 страницах; боковое меню на телефоне — выдвижная панель, на десктопе — постоянное; диалоги помещаются на экране 375×667; публичная запись помещается на 320 px на всех шагах.

## Найденные ошибки и что сделано
| # | Ошибка | Исправление |
|---|---|---|
| 1 | Формы входа и регистрации очищали все поля после неудачной отправки (React 19 сбрасывает форму после action): после неверного пароля приходилось вводить email заново. | `auth-form.tsx`: отправка через `onSubmit` + `startTransition`, `method="post"` (данные не попадут в URL, если форму отправят до гидратации). Тест проверяет, что email остаётся. |
| 2 | Тесты выявили, что события до гидратации теряются (клик по кнопке сразу после загрузки ничего не делает). | Это свойство React (ленивая гидратация), в приложении не менялось; в тестах — `open()` ждёт сеть, `openDialog()` повторяет клик до появления диалога. |

Остальные падения во время разработки тестов были ошибками самих тестов (неверные ожидания про формат расписания, `strict mode` из-за скрытого `role="alert"` Next.js, зависимость от порядка и исчерпание свободного времени общей БД) — исправлены в тестах, поведение приложения не менялось.
Ошибки, найденные тестами и исправленные на предыдущих этапах: падение меню пользователя (`MenuGroup`), пустая цена услуги принималась как 0, перенос и валидация записей.

## Оставшиеся проблемы и ограничения
- Стенд — эмулятор, а не настоящий Supabase: поведение PostgREST/GoTrue (формат ошибок, лимиты, письма подтверждения) не проверено. Перед релизом стоит один раз прогнать `npm run e2e` на настоящем проекте (нужны ключи тестового проекта).
- Перетаскивание записи проверено через эмуляцию мыши Playwright; на сенсорных экранах перенос возможен только через форму «Изменить».
- Тесты зависят от seed-данных (демо-салон «Лаванда») и общей базы: запускаются последовательно (`workers: 1`).
- В dev-режиме (`next dev`) Next.js показывает предупреждения про `Date.now()` и «uncached data»; в production-сборке и в тестах их нет.
- Не покрыто: письма/SMS клиенту (их нет в продукте), отмена записи клиентом (не реализована), проверка доступности для скринридеров (кроме ролей и меток, на которых построены селекторы), реальная нагрузка и лимиты по IP за прокси (в тестах IP подставляется заголовком `x-forwarded-for`).
- Для несуществующего адреса `/book/<slug>` страница показывает «не найдено», но статус ответа 200 (потоковая отрисовка Next).
